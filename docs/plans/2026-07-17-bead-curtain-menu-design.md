# 垂珠選單設計

## 目標

在獨立的 `mazu-beta` 網站保留既有官網的 Supabase 後台、會員中心、報名與捐獻資料流，只更新公開首頁的導覽體驗，加入 beta 版本的垂珠選單。

## 方案比較

1. 直接以 beta 專案取代原站：視覺最接近 beta，但會遺失目前已上線的後台與 Supabase 功能，不採用。
2. 只將 beta 的垂珠選單元件搬入原站：保留現有資料層與頁面功能，並把選單點擊接回既有的捲動與頁面切換行為，採用。
3. 重寫整個導覽與首頁：彈性較高，但風險與範圍都不必要地擴大，不採用。

## 架構

新增獨立的 `BeadCurtainMenu` React 元件，接收目前導覽區段與點擊回呼。元件使用動畫函式庫呈現垂珠擺動，並透過按鈕語意、鍵盤焦點與標籤保留可及性。原本的 `scrollToSection`、會員中心、經文頁與行動版漢堡選單維持其原有資料與路由行為。

桌面版導覽會以垂珠選單取代文字連結；手機版保留緊湊的漢堡選單，避免垂珠過長而遮住內容。登入與會員入口保持可見，桌面版以圖示按鈕呈現。

## 資料與安全

不更動 Supabase schema、RLS 或後台 API。部署時使用原 Supabase 專案的公開 URL 與 publishable/anon key，僅存在本機 `.env.local` 與新 Vercel 專案的環境變數中；任何個人存取權杖不會寫入程式碼、git 或前端 bundle。

## 錯誤處理與驗證

動畫在不支援 Web Audio 或使用者偏好減少動態效果時仍可點擊導覽。建立元件測試覆蓋選單項目、目前區段標示與點擊回呼；再執行型別檢查、production build，以及桌面和手機 viewport 的瀏覽器驗證。最後確認新 Vercel 專案名稱與既有專案不同。
